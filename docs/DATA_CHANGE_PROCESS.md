# إجراء تغيير البيانات — Data Change Process

أي إضافة حقل مهم، أو تغيير معنى حقل، أو تغيير مفردة معيارية، أو تغيير في مصفوفة الوصول يمر بالمسار التالي. إصدار المخطط الحالي: **1.3** (رأس `convex/schema.ts`).

## المسار
1. **الحاجة**: يُفتح طلب تغيير بيانات (Data Change Request) يصف: الجدول/الحقل، السبب التجاري، من يقرأ ومن يكتب، الحساسية (D1–D4)، الأثر على الوكلاء والتقارير.
2. **المراجعة**: مراجعة فنية (اتساق مع `vocab.ts`/`baseFields.ts`، فهارس، حدود Convex) ومراجعة بيانات (هل يوجد حقل مكافئ؟ مبدأ المصدر الواحد).
3. **اعتماد المالك**: يُسجَّل في `decisionRegister` بنوع `POLICY_APPROVAL` مع النطاق وتاريخ النفاذ.
4. **الترحيل**:
   - الحقول الجديدة تُضاف `v.optional(...)` أولاً، تُنشر، تُملأ (backfill عبر `@convex-dev/migrations` أو دالة داخلية)، ثم تُشدَّد إن لزم.
   - تغيير مفردة: تُضاف القيمة الجديدة إلى `vocab.ts` (تُفرض في المخطط) وتُحدَّث `VOCAB_AR` وخرائط التسلسل `*_TRANSITIONS`.
   - تغيير مصفوفة الوصول: صف جديد في `dataAccessMatrix` بـ`grantedBy = owner` (صفوف النظام تُستبدل عند كل bootstrap؛ صفوف المالك لا تُمس).
5. **الاختبار**: اختبار وحدة/تكامل في `convex/tests` يثبت: قبول القيم المعيارية ورفض غيرها، الحماية على مستوى الحقل/الصف، التدقيق. `npm test` و`npm run build` ناجحان.
6. **الإصدار**: رفع إصدار المخطط (1.0 → 1.1 للإضافات المتوافقة، 2.0 للتغييرات الكاسرة) في رأس `schema.ts`، وتحديث:
   - `docs/DATA_DICTIONARY.md` (الحقل، الاسم العربي، التعريف، النوع، القيم، الإلزامية، المصدر، المالك، الحساسية، قاعدة التحقق)
   - `docs/ERD.md` (العلاقات)
   - `docs/VOCABULARY.md` (المفردات والتسلسل)
   - `lib/entities.ts` إن كان الحقل يُدخل يدوياً (يولّد النموذج تلقائياً)
   - تعليمات الوكلاء المتأثرة (`agents` من الإعدادات) والتقارير (`KPI_DICTIONARY.md`)

## خطة التوافق
- **الوكلاء**: الأدوات تعيد الحقول الجديدة تلقائياً عبر طبقة الخدمات؛ يجب مراجعة `fieldDenyList` لكل وكيل قبل النشر حتى لا يتسرب حقل حساس جديد.
- **التقارير**: أي مؤشر يعتمد على حقل متغير يُحدَّث في `computeKpis`/`dashboard.ts` في نفس الطلب.
- **البيانات القديمة**: لا حذف نهائي؛ تُوسم `archivedAt` أو `supersededBy`. القيم غير المعروفة تُترك فارغة أو `UNKNOWN`/`NOT_PROVIDED`/`REQUIRES_VERIFICATION` ولا تُخمَّن.
- **الترحيل من Excel/PDF**: جرد → تصنيف → تنظيف → إزالة تكرار → تحقق → مطابقة حقول (واجهة الاستيراد) → استيراد بحالة `MIGRATED_UNVERIFIED` → مراجعة المالك ترفع الثقة (`records.verify`) → أرشفة الأصل كمستند في مصادر المعرفة.
